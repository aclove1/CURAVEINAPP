- `calcKeyMetrics` — consumed by `/scenario` for the top KPI strip (Avg Monthly Procs, Revenue/Proc, COGS/Proc, Stabilized EBITDA, Months at Capacity, Breakeven).
- `calcBreakeven` — its Y1 month loop iterated raw `a`, threading `cap=146` through every cumulative-EBITDA step.

### C-12. `calcRevenueMonth` payer split (medicare + commercial) diverges from `procRevenue` by ~6% — `/revenue` Monthly Detail totals row doesn't reconcile

**Issue.** `calcRevenueMonth` returns `medicareRevenue` and `commercialRevenue` for the `/revenue` table and chart breakdown:

```
medicareRevenue   = round(procs × govMix × medicareRate)
commercialRevenue = round(procs × commMix × commercialRate)
                    where commercialRate = round(medicareRate × commMultiplier)
```

But `grossRevenue` is `procs × blendedRate + usRevenue`, where `blendedRate` *includes the net realization factor* (Base 0.94) and `procRevenue` is the realized (post-write-off) procedure billing. The split lines did not include realization. The chart and table claim `Medicare Rev + Commercial Rev` reflect the procedure portion of gross — but they don't:

| Scenario     | Pre-fix Σ(med + comm) | Pre-fix procRevenue (gross − usRev) | Δ       |
|--------------|-----------------------|--------------------------------------|---------|
| Conservative | $1,457,510            | $1,209,639                           | +20.5%  |
| Base         | $1,506,685            | $1,416,554                           | +6.4%   |
| Aggressive   | $2,880,562            | $2,766,192                           | +4.1%   |

The Conservative gap is ~$248K — directly attributable to the 0.83 realization factor never being applied to the split. On `/revenue/page.tsx` the table column "Medicare Rev | Commercial Rev | Gross Revenue" reads as a three-piece summation that anyone with a calculator could disprove in 30 seconds. Same gap shows up in the stacked-bar chart, where the bars are stacked under a "Gross Revenue" implication.

**Impact.** Same class of failure as the prior C-7 (`EbitdaTooltip` on the Gross Revenue chart): a label promising a relationship the math doesn't deliver. Diligence-fail.

**Fix (implemented).**
1. `calcRevenueMonth` (`lib/model.ts:246`) — derive the split from `procRevenue` itself with commercial as the residual:
   ```ts
   const denom = govMix + commMix * commMultiplier
   const medicareShare = denom > 0 ? govMix / denom : 0
   const medicareRevenue = Math.round(procRevenue * medicareShare)
   const commercialRevenue = procRevenue - medicareRevenue
   ```
   This guarantees `medicareRevenue + commercialRevenue == procRevenue` to the dollar, no rounding gap.
2. `RevenueMonth` (`lib/types.ts:165`) — added `usRevenue: number` so callers can show the third leg explicitly. Was previously folded into `grossRevenue` with no breakout.
3. `/revenue/page.tsx` (table + chart) — added a "US Revenue" column to the Monthly Detail table and a third stack to the Medicare/Commercial chart so the bars literally sum to gross. Caption clarified.
4. `/api/audit/route.ts` — `usRevenue` now exposed in the JSON dump so external consumers can verify `medicareRevenue + commercialRevenue + usRevenue == grossRevenue`.

**Reconciliation (post-fix):**

```
[C-12] med + comm + us == gross (per-month, exact):  ✓  (maxΔ=$0)
Annual: $301,813 + $1,114,742 + $332,444 = $1,748,999  vs gross=$1,748,999  Δ=$0
```

Annotated `AUDIT 2026-04-26 C-12`.
